# The privileged path

*How to give the bot one real power (a shell, the network, a write outside its folder) without handing the model a shell. The privileged path and the [approval card](approval-card.md) are one idea: power lives in a fixed script you wrote, the model can only choose and draft, and when the effect reaches past you, a person taps a card that shows exactly what will run.*

Written against Claude Code 2.1.240 (September 2026). The card itself, and how to verify it, is in [approval-card.md](approval-card.md).

---

## Adding a privileged capability without opening a shell

Eventually you'll want the bot to *do* something that genuinely needs a shell + network, e.g. transcribe a video link (download with `yt-dlp`, extract audio with `ffmpeg`, run a local Whisper model). You do **not** want to hand the LLM a general Bash to achieve that.

The pattern: a **scoped dispatcher**.

```js
function onMessage({ userId, text }) {
  if (/(?:some-video-host)\.com/.test(text)) return handlePrivileged(userId, text);
  return handleChat(userId, text);     // the files-only path from README §5
}
```

`handlePrivileged` runs a **fixed pipeline script**: one you wrote, that the model cannot modify or parameterize beyond a vetted input (the URL). The LLM is still only used afterward, on the *files-only* path, to clean up / save the result. Keep this path narrow and document it. Only route **typed** text here: a voice-note transcript that happens to contain "youtube.com" must never reach the privileged path.

Two launchd-specific gotchas apply to this path, both in [gotchas.md](gotchas.md) (#6 and #8).

## One idea, two shapes

The dispatcher above and the approval card look like two features. They are the same rule applied at two moments.

**The rule: the model never runs the powerful thing.** Code you wrote runs it, with inputs you can check. The model's job is at most to *choose* among a closed set of actions and to *draft* the values; the program does the rest.

- **When the input is typed by you and checked by code** (a URL that matches a pattern, in text you typed, not a transcript), the program can run the fixed script straight away. That is the dispatcher above. The model is not in the loop at all until the result is back on the files-only path.
- **When the input was drafted by the model, or the effect reaches past you**, the program shows the exact draft on a card and waits. A person taps; the program executes the pinned draft, not a fresh answer from the model. That is the [approval card](approval-card.md).

So before you add a privileged path, read it against the card's four tests (in [approval-card.md](approval-card.md)): someone other than you can see the result; it touches real money or a ledger; it cannot be undone; the value being written was generated by the model. If none is true, as for a transcript saved into your own folder, a fixed script with a vetted input is enough. If any one is true, the path ends in a card.

Closed choices are safe to hand the model; an open output (a literal command, a free-form path, a recipient it picked) never is. If you find yourself letting the model fill in the command itself, you have built a general shell with extra steps.

The privileged path sits behind the same sender allowlist as everything else, and it goes into your Writes cell in [EIGHT-CELLS.md](../EIGHT-CELLS.md) by name: what it can change, and what it must never touch.

## Checklist lines this chapter adds

- [ ] One *audited, fixed-script* privileged path at most, reachable only from typed text.
- [ ] The model never fills in a command, path or recipient for the privileged path; it chooses from a closed set and drafts values at most.
- [ ] Every privileged action read against the four approval-card tests; any action that passes one goes through a card.
- [ ] The privileged path listed by name in the Writes cell.
